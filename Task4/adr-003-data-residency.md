# ADR-003: Стратегия размещения данных и комплаенса (Data Residency & Late Binding)

## Метаданные
* **Статус**: Принято (Accepted)
* **Дата**: 2026-08-25
* **Автор**: Solution Architect
* **Стейкхолдеры**: Амина Диоп (Lead Legal), Марк Лефевр (CEO), Раджеш Менон (CTO), Алекс Вебер (CFO)

---

## 1. Контекст и проблематика (Context)

Africa Delivery запускается в Нигерии, Кении и ЮАР. Законодательство Нигерии (**NDPR / NDPA**) предписывает локализацию персональных данных граждан, однако у ведущих облачных провайдеров (AWS, Google, Microsoft) отсутствуют дата-центры на территории Нигерии (ближайший регион AWS находится в ЮАР — Cape Town).

Юридический департамент уведомил команду, что финальное официальное заключение с детальными требованиями будет готово только через 4–6 недель (за 2 недели до запуска). Юристы рекомендовали «не фиксировать архитектуру». Однако остановка разработки означает гарантированный срыв дедлайна 15 октября.

Необходимо принять архитектурное решение, позволяющее вести разработку полным ходом, запустить MVP вовремя и адаптировать систему к любым юридическим предписаниям без переписывания кодовой базы.

---

## 2. Драйверы решений (Decision Drivers)

* **DD-01: Непрерывность разработки**: Не допустить блокировки разработки из-за ожидания юридического заключения.
* **DD-02: Принцип позднего связывания (Late Binding / Reversibility)**: Архитектура размещения данных должна быть на 100% обратимой и конфигурируемой за время $< 4$ часов.
* **DD-03: Юридическая безопасность**: Исключение риска блокировки со стороны регулятора данных Нигерии (NDPC) или штрафов по POPIA.
* **DD-04: Экономическая целесообразность**: Отсутствие необходимости арендовать дорогостоящие локальные серверы в Лагосе до подтверждения юридической необходимости.

---

## 3. Решение (Decision Outcome)

Принять архитектурный паттерн **Токенизированного хранилища персональных данных (Tokenized PII Vault & Pseudonymization)**:

```
[Клиентский запрос]
        │
        ▼ (HTTPS)
[API Gateway / Core App (AWS Cape Town)]
        │
        ├──────────────────────────────────────────────┐
        │                                              │
        ▼ (Транзакционные данные с UUID)               ▼ (Шифрованный mTLS вызов по токену)
[Основная БД PostgreSQL (Cape Town)]           [Изолированный PII Vault Service]
- orders (customer_uuid, total, status)         - pii_records (token_uuid, name, phone, address)
- catalog (items, prices, stock)                - Развертывание: AWS Cape Town / VPS Lagos
- billing (merchant_id, amount)                 - Ключи шифрования: AES-256 (KMS)
```

### Ключевые компоненты решения:
1. **Псевдонимизация ядра**: Все модули платформы (Каталог, Заказы, Склад, Биллинг, Аналитика) оперируют исключительно синтетическими суррогатными ключами (`customer_token_uuid`). База данных в AWS Cape Town **не содержит открытых персональных данных граждан**.
2. **Изолированный сервис `PII Vault`**: Выделенный микромодуль, отвечающий за операции детокенизации (например, расшифровка адреса и телефона курьеру в момент передачи заказа на доставку).
3. **Консервативное допущение до запуска 15 октября**:
   - На этапе разработки и старта MVP сервис `PII Vault` разворачивается в изолированной защищенной подсети AWS Cape Town;
   - Если через 4–6 недель юристы подтвердят жесткое требование хранения данных нигерийцев в Лагосе — контейнер `PII Vault` разворачивается на локальном VPS в дата-центре **MainOne (Лагос)** за 2 часа простым изменением адреса в переменной окружения `PII_VAULT_URL`.

## 4. Оценка обратимости решения (Reversibility Matrix)

| Юридический сценарий через 4–6 недель | Действия команды архитекторов / DevOps | Трудозатраты | Влияние на кодовую базу |
|---|---|---|---|
| **Сценарий A: Допускается трансграничная передача при наличии Opt-in согласия** | Оставить `PII Vault` в AWS Cape Town, включить Double Opt-in чекбокс на фронтенде. | 0 часов | 0 строк кода |
| **Сценарий B: Жесткое требование суверенного хранения ПДн в Нигерии** | 1. Развернуть контейнер `PII Vault` на VPS в Лагосе (MainOne).<br>2. Перенаправить сетевой трафик через `PII_VAULT_URL`. | 4 часа DevOps | 0 строк кода |
| **Сценарий C: Требование локализации в каждой стране присутствия** | Развертывание мульти-экземпляров `PII Vault` в Кении, Нигерии и ЮАР с маршрутизацией по коду страны (`+234`, `+254`, `+27`). | 1 спринт | Минимальные правки в шлюзе маршрутизации |

## 5. Последствия (Consequences)

### Положительные:
* **Разработка не блокируется**: Команда ведет разработку в соответствии с графиком к 15 октября;
* **Нулевой риск переписывания системы**: Основное бизнес-ядро не зависит от географии размещения серверов персональных данных;
* **Защита от штрафов**: Даже при утечке базы заказов в ней содержатся только обезличенные UUID.

### Отрицательные и компенсирующие меры:
* *Сетевая задержка при вызове PII Vault*: Детокенизация выполняется только на финальных этапах жизненного цикла (печать накладной, отправка SMS курьеру), не затрагивая быстрый поиск по каталогу.
