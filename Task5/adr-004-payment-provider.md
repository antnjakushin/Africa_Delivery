# ADR-004: Выбор платёжного провайдера и архитектуры платёжной оркестрации

## Метаданные
* **Статус**: Принято (Accepted)
* **Дата**: 2026-08-25
* **Автор**: Solution Architect
* **Стейкхолдеры**: Марк Лефевр (CEO), Раджеш Менон (CTO), Алекс Вебер (CFO)

---

## 1. Контекст и финансовые ограничения (Context)

Платежный ландшафт в Африке фрагментирован по странам:
- **Кения**: Более 80% всех транзакций e-commerce совершаются через мобильные деньги **M-Pesa (Safaricom)**;
- **Нигерия**: Доминируют наличные при получении (**Cash on Delivery** — 60%), локальные банковские переводы и карты **Verve / Mastercard / Visa**;
- **ЮАР**: Банковские карты (Visa/Mastercard) и мгновенный EFT (Electronic Funds Transfer).

Финансовый директор (**Алекс Вебер**) установил жесткий норматив Unit-экономики: **совокупная комиссия за эквайринг не должна превышать 2.5% от GMV**. CTO предлагал разработать собственную платежную систему с нуля.

---

## 2. Драйверы решений (Decision Drivers)

* **DD-01: Экономика**: Комиссия провайдера $\le 2.5\%$ от суммы транзакции.
* **DD-02: Time-to-Market**: Срок интеграции $\le 2$ недель (к 15 октября).
* **DD-03: Географический охват**: Нативная поддержка M-Pesa (Кения), карт Verve/Visa (Нигерия, ЮАР) и COD.
* **DD-04: Безопасность (Out-of-Scope PCI DSS)**: Отсутствие необходимости сертификации платформы по дорогостоящему стандарту PCI DSS на этапе MVP.

---

## 3. Решение (Decision Outcome)

Принять **гибридную стратегию платёжной оркестрации на базе паттерна Strategy / Adapter**:

```
                                  ┌───────────────────────────────┐
                                  │   Payment Orchestrator (Go)   │
                                  └──────────────┬────────────────┘
                                                 │ Strategy Routing
                ┌────────────────────────────────┼────────────────────────────────┐
                ▼                                ▼                                ▼
  ┌───────────────────────────┐    ┌───────────────────────────┐    ┌───────────────────────────┐
  │   M-Pesa Daraja Adapter   │    │    Flutterwave Adapter    │    │       COD Handler         │
  │    (Кения / Airtel)       │    │  (Нигерия / ЮАР / Карты)  │    │  (Наличные курьеру)       │
  └─────────────┬─────────────┘    └─────────────┬─────────────┘    └─────────────┬─────────────┘
                ▼                                ▼                                ▼
     Safaricom M-Pesa API             Flutterwave Host Checkout              Диспетчер курьеров
      (Комиссия: 1.5%)                  (Комиссия: 1.4–2.2%)                  (Комиссия: 0%)
```

### Выбранные провайдеры:
1. **Кения**: Прямая интеграция с **Safaricom M-Pesa Daraja API (STK Push)**. Комиссия: **1.5%** за транзакцию.
2. **Нигерия и ЮАР**: Интеграция с агрегатором **Flutterwave** (с резервным шлюзом **Paystack**). Комиссия: **1.4%** по локальным картам Нигерии (Verve), **2.2%** по международным картам (Visa/Mastercard), что строго $\le 2.5\%$ GMV.
3. **Cash on Delivery (COD)**: Встроенный обработчик в стейт-машину заказов с фиксацией инкассации курьером.

---

## 4. Последствия (Consequences)

### Положительные:
* **Соблюдение финансового норматива**: Средневзвешенная комиссия платформы составит **$pprox 1.65\%$ от GMV** (экономия бюджета CFO);
* **Запуск за 2 недели**: Использование официальных SDK и Host Checkout страниц исключает разработку платежных форм и снимает требования PCI DSS с Africa Delivery;
* **Отказоустойчивость**: При сбое M-Pesa или карт система мгновенно переключается на Cash on Delivery.
