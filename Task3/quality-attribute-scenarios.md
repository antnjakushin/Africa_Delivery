# Сценарии качественных атрибутов (Quality Attribute Scenarios — QAS)

Сценарии оформлены строго по 6-факторной структуре SEI (Software Engineering Institute).

---

### Сценарий 1 (QAS-01: Доступность при сбое зоны доступности AWS)
1. **Источник стимула (Source)**: Авария оборудования в одном из дата-центров региона AWS Cape Town (`af-south-1a`).
2. **Стимул (Stimulus)**: Полный отказ зоны доступности `af-south-1a`, потеря 1 пода приложения и Primary инстанса PostgreSQL.
3. **Артефакт (Artifact)**: Вычислительный кластер ECS Fargate и база данных RDS PostgreSQL Multi-AZ.
4. **Среда (Environment)**: Нормальный режим эксплуатации под рабочей нагрузкой (100 RPS).
5. **Реакция (Response)**: ALB автоматически исключает неисправный инстанс из пула; AWS RDS выполняет автоматический Failover на Standby узел в зоне `af-south-1b`; приложение переподключается к новому мастеру через пул соединений.
6. **Мера реакции (Response Measure)**: Время восстановления (RTO) $\le 60$ секунд; потеря зафиксированных транзакций (RPO) = 0; уровень ошибок для пользователей $\le 0.05\%$ запросов (с автоматическим повтором на клиенте).

### Сценарий 2 (QAS-02: Производительность витрины в сетях 2G/3G)
1. **Источник стимула (Source)**: Покупатель с бюджетным Android-смартфоном через мобильную сеть 3G (задержка RTT 250 мс, пропускная способность 512 кбит/с).
2. **Стимул (Stimulus)**: Открытие главной страницы каталога товаров и переход в категорию.
3. **Артефакт (Artifact)**: CDN CloudFront PoP (Лагос/Найроби), Redis Cache, PWA-клиент.
4. **Среда (Environment)**: Пиковый час после выхода рекламы на радио (150 RPS к витрине).
5. **Реакция (Response)**: Статические ассеты (HTML/JS/CSS, WebP изображения) отдаются из локального PoP CDN; JSON-структура каталога считывается из оперативной памяти Redis Cache без обращения к диску PostgreSQL.
6. **Мера реакции (Response Measure)**: Время до первого отображения товара (Time to First Meaningful Paint) $< \mathbf{1.8	ext{ секунды}}$; размер начального бандла страницы $< \mathbf{3.5	ext{ МБ}}$.

### Сценарий 3 (QAS-03: Отказоустойчивость при падении платёжного провайдера M-Pesa)
1. **Источник стимула (Source)**: Внешний сбой на стороне телеком-оператора Safaricom (деградация шлюза M-Pesa Daraja API).
2. **Стимул (Stimulus)**: Ответы `HTTP 504 Gateway Timeout` и рост задержки вызовов STK Push свыше 10 секунд.
3. **Артефакт (Artifact)**: Модуль `Payment Engine` и Circuit Breaker.
4. **Среда (Environment)**: Высокая активность оформления заказов (пятничный вечер, Кения).
5. **Реакция (Response)**: Срабатывает Circuit Breaker (переход в состояние `OPEN`); система блокирует зависающие вызовы к M-Pesa; фронтенд уведомляет пользователя о временной недоступности мобильных денег и предлагает альтернативу — оплату наличными при получении (COD) или банковской картой.
6. **Мера реакции (Response Measure)**: Время отсечения сбойного шлюза $\le 5$ секунд; предотвращение исчерпания пула потоков веб-сервера; 0 потерянных корзин пользователей.

### Сценарий 4 (QAS-04: Масштабируемость при всплеске трафика в 5 раз)
1. **Источник стимула (Source)**: Запуск рекламы на ключевых радиостанциях Найроби и Лагоса в 18:00.
2. **Стимул (Stimulus)**: Резкий скачок трафика с 30 RPS до **200 RPS** в течение 2 минут.
3. **Артефакт (Artifact)**: AWS Application Auto Scaling (ECS Fargate) и кэш Redis.
4. **Среда (Environment)**: Продакшн-среда, запуск рекламной кампании 15 октября.
5. **Реакция (Response)**: Утилизация CPU контейнеров превышает 70%; CloudWatch триггерит масштабирование ECS Fargate с 3 до 8 инстансов; Redis справляется с возросшей нагрузкой на чтение без деградации.
6. **Мера реакции (Response Measure)**: Дополнительные контейнеры вводятся в строй за $\le 90$ секунд; 95-й процентиль времени отклика (p95 latency) не превышает **450 мс**; 0 отказов в обслуживании (HTTP 503).

---

### Сценарий 5 (QAS-05: Безопасность и комплаенс при попытке несанкционированного доступа к ПДн)
1. **Источник стимула (Source)**: Внешний злоумышленник или скомпрометированный внутренний сервис.
2. **Стимул (Stimulus)**: Попытка прямого SQL-запроса или неавторизованного API-вызова к таблицам персональных данных покупателей (номера телефонов, адреса, имена).
3. **Артефакт (Artifact)**: Модуль `PII Token Vault` с разграничением привилегий на уровне PostgreSQL Role-Based Access Control (RBAC).
4. **Среда (Environment)**: Штатная эксплуатация.
5. **Реакция (Response)**: Запрос блокируется на уровне схемы БД (отсутствие прав у роли `app_order_user`); событие несанкционированного доступа логируется в защищенный аудит-лог с генерацией алерта ИБ.
6. **Мера реакции (Response Measure)**: Утечка персональных данных = 0 записей; время фиксации инцидента в журнале безопасности $< 1$ секунды; соответствие требованиям NDPR / POPIA.
