# ADR-002: Стратегия кеширования и обеспечения доступности данных

## Метаданные
* **Статус**: Принято (Accepted)
* **Дата**: 2026-08-25
* **Автор**: Solution Architect
* **Стейкхолдеры**: Марк Лефевр (CEO), Раджеш Менон (CTO), Алекс Вебер (CFO)

---

## 1. Контекст и проблематика (Context)

Мобильный интернет в целевых странах (Нигерия, Кения) характеризуется высокой задержкой (RTT 150–300 мс) и нестабильной скоростью в сетях 2G/3G. При этом маркетинговый бриф требует время загрузки витрины **$< 2.0$ секунд**, а инвестор ожидает устойчивость при всплесках рекламного трафика.

Прямые запросы к базе данных PostgreSQL при каждом открытии каталога приведут к исчерпанию пула соединений и деградации производительности. Необходимо внедрить многоуровневую стратегию кэширования, обеспечивающую мгновенный отклик и разгрузку БД при минимальной стоимости.

---

## 2. Драйверы решений (Decision Drivers)

* **DD-01: Performance**: Время отдачи карточек товаров и каталога $< 200$ мс на стороне сервера.
* **DD-02: Availability**: Способность отдавать каталог даже при временной деградации основной БД (Graceful Degradation).
* **DD-03: FinOps & Simplicity**: Стоимость решения в рамках $300/мес (AWS ElastiCache Redis + CloudFront).
* **DD-04: Data Freshness**: Обновление цен и остатков не позднее 30 секунд после изменения мерчантом.

---

## 3. Решение (Decision Outcome)

Принять **трехуровневую архитектуру кэширования (Multi-Tier Caching)**:

```
[Покупатель] ──► [1. Edge CDN (CloudFront)] ──► [2. In-Memory Cache (Redis)] ──► [3. Database (PostgreSQL)]
```

### Уровень 1: Edge CDN (AWS CloudFront + Cloudflare)
* **Область применения**: Статический контент (картинки товаров в WebP, CSS/JS бандлы PWA).
* **Политика**: `Cache-Control: public, max-age=86400, immutable` для версионированных ассетов.
* **Точки присутствия**: Edge PoP в Йоханнесбурге, Кейптауне, Найроби и Лагосе.

### Уровень 2: Distributed In-Memory Cache (AWS ElastiCache Redis Cluster)
* **Область применения**:
  1. Дерево категорий и меню каталога (TTL = 24 часа);
  2. Популярные товары и списки категорий (TTL = 15 минут);
  3. Детальные карточки товаров (TTL = 5 минут);
  4. Сессии пользователей и временные корзины (TTL = 7 дней).
* **Паттерн**: **Cache-Aside** с поддержкой **Stale-While-Revalidate**:
  - При промахе кэша сервис читает БД, сохраняет значение в Redis и возвращает клиенту;
  - При обновлении цены/остатка мерчантом — прямая инвалидация ключа (`DEL product:{id}`) через доменное событие `ProductUpdated`.

### Уровень 3: Защита от сбоев базы данных (Degraded Mode)
* Если PostgreSQL недоступен, Redis продолжает отдавать закэшированные страницы каталога, предотвращая «белый экран» для покупателей.

---

## 4. Последствия (Consequences)

### Положительные:
* **Снижение нагрузки на PostgreSQL на 85–90%**;
* **Время отклика API каталога снижается до 15–30 мс**;
* **Соблюдение NFR $< 2.0$ сек** даже в сетях 3G.

### Отрицательные и компенсирующие меры:
* *Риск «протухания» остатков (Race condition при покупке последнего товара)*: Окончательная проверка остатка и блокировка выполняются строго на уровне транзакции PostgreSQL в момент нажатия кнопки «Оплатить заказ».
